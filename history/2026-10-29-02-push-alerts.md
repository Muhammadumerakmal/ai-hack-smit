# Push alerts on phones and computers (Web Push)

- **Date:** 2026-10-29
- **Commits:** see git log
- **Tests:** npm test: 280 (8 new: 6 push, 2 matrix entries). One run had the CSV perf test at 47 s while a build and a browser were running; it passed alone. Typecheck and lint clean; production build.

## Changes
- **What it does:** every in-app notification is also a phone/computer alert, like YouTube notifications, even with the site closed: leave approved, rejected or cancelled, payslip ready, announcement, attendance correction decided, face reset.
- **Server:** the `PushSubscription` table (company-scoped, unique endpoint, cascades with the user). `push.service.ts` has subscribe/unsubscribe (the same device re-subscribing as another user is re-owned), `deliverPush` (only rows that exist, i.e. committed; removes devices on 404/410) and `queuePush` (Next `after()`, in the same company). `notify()` uses `createManyAndReturn` to get the ids. The route is `GET/POST/DELETE /api/push` (all roles; allowed before the first password change). Library: `web-push` 3.6.7 with VAPID keys.
- **Browser:** `public/sw.js` handles `push` (shows title, body and icon; `tag` = notification id, so no duplicates) and `notificationclick` (opens the link, reusing an open tab). `PushToggle` sits in the bell menu, with states on/off, blocked (how to allow), iPhone (add to Home Screen first), unsupported, and hidden when the server has no keys.
- **Safe before the database migration:** without VAPID keys the push table is never read or written, so deploying this to a database that doesn't have the table yet changes nothing.
